# How do I interpret user needs and implement them into a program? How does creating “user stories” help with this?

Users stories help change the focus of development. Before designing and coding systems I now know its more worthwhile to gather user stories to get feedback on what the user is trying to solve as well. 
Knowing what they want out of the system or product is more important and allows us to remain user focused. The main benefit on the production side, is that it gives us clear definitions of when a feature is done and allows us to give rankings to each feature based off the importance. 

# How do I approach developing programs? What Agile processes do I hope to incorporate into my future development work?

I personally already followed some Agile principles on my previous development projects for reference. The most important thing I learned is that work can be done on completely unrelated features instead of fully completing each thing before moving on. The most important aspect is getting to the MVP stage and then letting user stories and internal standup meetings guide the rest of the progression. The Daily standup is something that I can't implement in a solo capacity, but even by myself I can attempt to use the structure to better prioritize my work. Lastly, I will be using a kanban board from here on out so I don't have to have so many TODO documents cluttering my documents folder. 

# What does it mean to be a good team member in software development?

Accountability is at the forefront of being a good team member. When integrated within a team using an Agile framework there is more autonamy than usual. 
Your team members will be depending on you to be self motivated and held accountable for everything you do. I think its also important to stay flexible and step into different shoes as required by the team. 
You must see yourself as a member of a unit rather than as an individual.
